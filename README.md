# 研策台

这是一个支持云端部署的 A 股研究与复盘工具。它由两层组成：

- 规则层：稳定识别涨跌幅、放量、均线、20 日高低点、接近止损等客观信号。
- LLM 层：支持在页面配置 DeepSeek、OpenAI 或其他 OpenAI 兼容模型，基于规则信号生成个股研判、收盘复盘、风险提示和下一步追问。
  个股研判会在调用模型前尝试抓取最新公开新闻、公告事件和解禁信息；每日简报会补充最多 8 只股票的公开行情、新闻、公告事件和财务摘要，再与浏览器中的规则报告合并后交给模型。

它不会自动下单，也不提供投资建议。它的目标是帮你更稳定地整理信息、发现异动、记录交易纪律。

## 本地数据与云端部署

项目采用“云端无状态服务 + 浏览器本地数据”的方式：页面和行情接口可以部署到云端，但每位用户的自选股、持仓设置、观察计划、个股 AI 报告和每日 AI 简报都保存在该用户浏览器的 IndexedDB 中，不写入云数据库。

- 股票和 AI 报告：保存在当前站点的 IndexedDB。
- 大模型配置及 API Key：保存在当前浏览器、当前站点的 `localStorage`，不会写入项目文件、IndexedDB、云数据库或 JSON 备份。
- 代理模式下，API Key 和分析内容会随单次请求经过当前站点服务端；服务端不持久化这些配置。
- 浏览器直连模式下，API Key 和完整分析内容直接发送给模型服务商。生成每日简报时，当前站点只接收最多 8 只股票的代码、名称和观察风格，用于补充公开信息；持仓状态、仓位比例、观察理由、用户备注和规则报告在浏览器中合并，不提交给外部信息补充接口。
- 公共行情、财务、公告和新闻：由无状态接口即时查询，服务端不保存用户自选股或持仓。
- 不同浏览器、不同浏览器用户配置和不同域名之间的数据相互隔离。
- 清理站点数据、卸载浏览器或更换电脑可能导致数据丢失，应定期使用“导出本地备份”。

首次打开升级后的版本时，原先存放在 `localStorage` 中的股票数据会自动迁移到 IndexedDB。

## 是否使用了 LLM

LLM 是可选层，由页面右上角的“大模型配置”管理。

- 未配置大模型时：页面仍可使用规则分析功能。
- 点击“验证并保存”后，页面会实际连接模型并显示配置成功或具体错误；验证成功后才会保存配置。
- 配置成功后：可以生成个股策略报告和每日简报的 LLM 解读。
- 调用方式共有三种：**自动**、**浏览器直连**、**当前网站无状态代理**。
  - **自动**：优先从浏览器直接调用；仅在跨域或网络传输失败时回退到当前网站代理。当前页面会话确认直连不可用后，后续生成会直接使用代理，连接配置变化时才重新检测。
  - **浏览器直连**：API Key 和完整分析内容直接发送给模型服务商，模型接口必须支持浏览器 CORS；每日简报的公开信息补充仍会把股票代码、名称和观察风格发送给当前站点。
  - **当前网站无状态代理**：单次请求经过当前站点的 `/api/llm`；本地启动时由本地 Node 服务承载，云端部署时由站点 Function 承载。

LLM 不负责计算确定性指标，涨跌幅、量比、均线和风险触发仍由本地规则计算。保存后的模型配置只对当前浏览器和站点生效；清理站点数据或点击“清除配置”会删除这些信息。

## 怎么打开

### 云端访问

直接访问部署后的站点地址即可，不需要下载项目或安装其他程序。腾讯云等常驻 Node 环境应运行 `agent-server.js`，并由 Nginx 或云平台网关把站点请求转发到该服务。Vercel 部署需要为 `/api/health`、`/api/stock`、`/api/llm` 和 `/api/brief-context` 分别提供 Function 入口。

腾讯云自托管的完整流程（目录结构、Nginx 反代、pm2、回滚、发布后校验）见 [`deploy/DEPLOY.md`](deploy/DEPLOY.md)。日常发布只需执行：

```powershell
.\deploy\deploy.ps1
```

发布后访问 `/api/health`，其中 `build.commit` 用于确认线上实际运行的版本。

### 本地开发或本机使用

在项目目录运行：

```text
node agent-server.js
```

也可以双击 `StartAgent.bat`。服务启动后访问：

```text
http://localhost:8787/
```

完整功能必须通过上述本地服务或云端部署地址使用。`file://` 方式不支持行情和站点代理。

## 现在能做什么

- 查看你已添加自选股的涨跌幅、量比、短线趋势、长期质量和风险等级。
- 根据阈值自动生成提醒，包括涨跌幅、放量、突破 20 日高点、跌至 20 日低位、均线转弱、接近止损线和事件跟踪。
- 生成每日收盘简报，可复制或下载为 TXT。
- 点击任意个股，查看短线走势、财务质量、估值、风险提醒和下一步复盘问题。
- 使用页面配置的大模型生成个股研判和简报解读。
- 生成个股研判前会即时抓取最新公开新闻；抓不到时会明确显示数据不足，不会让模型编新闻。
- 生成每日简报时会补充最多 8 只股票的公开行情、新闻、公告和财务摘要；每只保留关键指标、最多 3 条新闻和 4 条事件，股票补充并发数为 3，并要求简报正文控制在 1000 字以内。输出上限统一使用配置里的“最大输出 Tokens”（默认 4096），不再单独限制简报。
- 导出或导入核心业务数据的本地 JSON 备份：股票（含持仓设置和观察计划）、个股 AI 报告、每日 AI 简报，以及已清空 API Key 的模型配置。备份不包含提醒阈值、搜索条件和当前页面状态。
- 直接输入股票代码添加/更新股票，并通过当前站点的 `/api/stock`（本地 Node 服务或云端 Function）获取价格、成交量、均线、20 日高低点等数据。
- 自动抓取公开公告/解禁/财务异常事件，命中减持、问询函、监管风险、财报异常、解禁压力时才显示提醒。
- 在个股页查看“数据来源”，区分实时行情、历史K线、财务摘要、公告事件和本地计算字段。

## 个股 AI 分析风格

AI 不提供单独的策略选择控件，而是直接读取个股设置中的“观察风格”。进入“个股”页后点击“生成策略报告”即可。需要改变分析周期或报告框架时，请先通过“编辑”修改该股票的观察风格。

- **短线观察**：面向数个交易日至数周，重点分析趋势与均线、量价配合、20/60 日区间、波动回撤和近期事件催化。
- **长期观察**：面向数个季度至数年，重点分析 ROE、营收与利润增长、现金流、负债、估值背景和长期逻辑失效条件。
- **短线+长期**：分别分析短期交易结构和长期基本面，并明确两个周期是一致、冲突还是互不支持。
- **风险观察**：风险优先，重点检查回撤、波动、止损距离、仓位暴露、趋势弱化、财务承压和公告事件。
- **等待确认**：不预设方向，重点整理已确认事实、支持因素、矛盾信号、数据缺口和形成判断前需要出现的证据。

所有风格都不提供直接买卖指令、目标价、建议仓位或收益预测；数据不足时必须明确说明，不得编造新闻、公告或财务数据。

## 数据源和口径

当前数据源分五类，页面会在个股页的“数据来源”区显示具体来源、接口地址、取数时间和失败原因。

- 实时行情：会同时请求东方财富 `push2.eastmoney.com`、腾讯证券 `qt.gtimg.cn`、新浪财经 `hq.sinajs.cn`，并按交易时间合并各来源的字段。不是只要一个接口成功就停止，而是会继续用后续来源补齐缺失字段。包括开高低收、昨收、涨跌、成交量额、换手、量比、PE/PB、市值和股本等。成交量统一换算成“股”后再计算量比。
- 历史K线：会同时请求东方财富 `push2his.eastmoney.com`、腾讯证券 `web.ifzq.gtimg.cn`，优先选择同时带有成交额和换手率的结果。均线、20/60日区间、均量均额、区间涨跌、波动率、最大回撤等由本地根据K线计算。
- 财务摘要：会扫东方财富 F10 和数据中心多个接口，包括 `emweb.securities.eastmoney.com`、`datacenter-web.eastmoney.com`，并合并各接口能拿到的字段。能取到时显示 ROE、营收/净利同比、负债率、毛利率、净利率、EPS、营收、净利润等。
- 公告事件：会尝试东方财富公告和解禁日程接口，按标题和日期窗口识别减持、问询函、监管风险、财报异常、限售股解禁。财务摘要出现净利/营收同比下滑超过 5%、净利润为负，或非金融行业的负债率偏高时，也会生成“财务指标承压”事件。没有命中风险事件时不显示。
- 最新新闻：生成个股 AI 研判或每日简报时，会通过东方财富资讯搜索接口抓取近期新闻标题、日期和来源，并与公告标题合并，作为 LLM 上下文。
- 简报公开信息：浏览器通过 `/api/brief-context` 提交最多 8 只股票的代码、名称和观察风格。接口按 IP 每分钟最多调用 6 次，并将股票补充并发限制为 3；返回内容在浏览器中与完整规则报告合并。
- 本地规则：量比、短线趋势、风险等级、质量标签、提醒队列由浏览器本地规则计算，不是外部接口直接给出的结论。

取不到的数据会显示“暂无”或“待补充”，不会用假数据填充。不同公开接口的字段覆盖不完全，所以并不是每只股票都会有同样完整的数据。

如果某个字段仍然缺失，个股页“数据来源”会显示已经尝试过的来源和失败原因。通常原因是该公开接口没有该字段、接口临时不可达、非交易时段返回不完整，或该股票本身没有对应财务字段。

## 添加股票与本地备份

在页面底部的“添加股票”区域输入 6 位 A 股代码，例如 `600519`，然后点击“添加/更新”。页面会通过当前站点的 `/api/stock` 获取并补齐真实行情、K 线、财务和事件数据；取不到的字段会保持为空或显示“待补充”。

页面右上角提供 JSON 备份：

- 点击“导出本地备份”下载核心业务数据。
- 点击“导入本地备份”选择此前导出的 JSON 文件，并用其中的核心业务数据恢复当前浏览器。
- 备份包含股票、个股 AI 报告、每日 AI 简报和去除 API Key 的模型配置，不包含提醒阈值、搜索条件或当前页面状态。

## 开发与验证

项目没有 `package.json`，无需安装依赖。可直接运行：

```text
node --check agent-server.js
node test-finance-parser.js
node test-agent-server.js
node test-stock-api.js
```

`test-stock-api.js` 是联网集成测试；`test-agent-server.js` 包含 DNS 校验，结果可能受网络环境影响。

### 服务端可调参数

| 环境变量 | 默认值 | 作用 |
|---|---:|---|
| `LLM_TIMEOUT_MS` | 本地 45000 / Vercel 22000 | 模型代理请求超时毫秒数 |
| `LLM_MAX_TOKENS` | 本地 3200 / Vercel 1800 | 服务端兜底输出上限，仅在请求未携带 maxTokens 时使用；页面配置优先 |
| `NEWS_TIMEOUT_MS` | 本地 9000 / Vercel 3500 | 新闻补充超时毫秒数 |
| `STOCK_RATE_LIMIT_MAX` | 30 | `/api/stock` 每 IP 每分钟请求上限 |
| `BRIEF_CONTEXT_RATE_LIMIT_MAX` | 6 | `/api/brief-context` 每 IP 每分钟请求上限 |
| `LLM_RATE_LIMIT_MAX` | 20 | `/api/llm` 每 IP 每分钟请求上限 |
| `STOCK_CACHE_TTL_MS` | 15000 | 股票数据缓存毫秒数 |

模型持续超时时，应先选择响应更快的模型或减少自选股数量，再根据部署平台限制调整 `LLM_TIMEOUT_MS`，不建议单纯无限提高超时。

### 云端常见问题

- **行业一直显示“待补充”**：行业字段主要来自东方财富行情和财务接口。云服务器出口 IP 可能被上游限流或返回不完整字段，而腾讯、新浪等备用行情源通常只能补充价格，不能补充行业。先在服务器检查 `push2.eastmoney.com` 是否返回 HTTP 200 以及 `f100`、`f127`、`f128` 字段。
- **简报提示模型响应超时**：每日简报包含公开信息补充和模型生成两个阶段。确认模型接口从服务器可达，并优先选择响应更快的模型；当前简报最多处理 8 只股票。代理超时由 `LLM_TIMEOUT_MS` 控制。
- **提示“本次输出达到上限”**：说明模型输出被 `max_tokens` 截断。个股报告和每日简报都使用页面配置里的“最大输出 Tokens”，直接在“大模型配置”里调高（建议 4096 以上）后重新生成即可。DeepSeek 等模型的思考模式默认开启，思维链同样消耗这部分额度，所以长简报需要比正文更大的预算。
- **简报公开信息接口 404**：确认网关或云函数已暴露 `/api/brief-context`。常驻 Node 部署由 `agent-server.js` 直接提供；使用按文件映射路由的云函数平台时，需要为该路径增加对应入口。
- **请求过于频繁**：`/api/stock`、`/api/brief-context` 和 `/api/llm` 都按客户端 IP 限流。反向代理必须正确传递可信的客户端 IP；否则所有访问者可能共享同一个出口 IP 配额。

## 建议的使用节奏

每天收盘后做一次：

1. 添加或刷新你的自选股真实行情数据。
2. 调整提醒阈值，比如涨跌幅 5%、放量 1.8 倍、距离止损 3%。
3. 看“今日提醒队列”。
4. 对高优先级股票进入“个股”页看规则分析，确认该股票的“观察风格”符合你的目标，再点“生成策略报告”。
5. 如需改变分析周期或框架，在“编辑个股设置”中修改观察风格后重新生成。
6. 进入“简报”页，点“生成LLM解读”，把输出贴到交易日志。
